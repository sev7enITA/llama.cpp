# Community fork review, 2 November 2026

## Scope and disposition

**Request changes before treating this wrapper as suitable for untrusted multi-party chat.** This is a bounded review, not a security audit or a qualification of the whole NodeLift product. Gemini 4 Argon High reviewed the full public `core.h`, `core.cpp` and original `bench.py` from fork commit `42458074580813661f1a35fa8da60107ee796fe7` after they were supplied in the prompt. Gemini said it had not run code and could not retrieve the linked GitHub files itself. It inspected only part of the showcase. GLM 5.3 Max was requested twice, including with the same source supplied directly; its service returned a capacity message. No GLM review result was received in this session.

## Adjudicated observations

1. **Untrusted text may introduce control tokens.** Gemini identified `parse_special=true` in tokenization. Two independent local checks on Llama 3.1 8B and Qwen2.5 0.5B found that a literal template delimiter embedded in the user text produced an additional delimiter token. [Results](tokenizer-review.json). This does not establish that a particular model obeys an injected instruction. The limitation is documented on the fork and release; the binary is not fixed. Do not treat the wrapper as isolating untrusted chat text from control tokens. A safe solution must preserve legitimate template tokens and be tested per model and integration.
2. **Benchmark provenance.** Gemini identified that the original runner hard-coded the Llama model label regardless of `--model`. A separate token check found an additional shared BOS token in both Llama suffixes: the recorded shared prefixes were 257 and 1,025 tokens, not the original base sizes. Both descriptions and future-run accounting were corrected, while historical results remain unchanged. A corrected runner was exercised on Qwen2.5 0.5B: all 12 pairs matched, with the supplied filename and actual shared lengths reported.
3. **Cancellation semantics require care.** The native ABI documents that each new call clears cancellation and that callers must gate future dispatch themselves. A queued call can therefore proceed after cancellation of a different active call; Gemini's suggested stronger cancellation semantics are not provided by this contract. No new race test or fix was made. Callers needing queued-request cancellation must implement and test that behavior.
4. **Error-path cache reset.** `nl_call` resets context on any exception, including invalid JSON. That can lose useful cache even if parsing failed before mutation. The reset is conservative: simply removing it, as suggested, would require proving that every other error path preserves consistent state. No change was applied.
5. **C ABI serialization on allocation failure.** Serialization of the result occurs outside the main `try` block. An allocation failure there may escape across the intended C interface; this is a static concern, not a reproduced crash. A fault-injection test and an explicit nullable return contract are needed before changing the ABI.
6. **Batch numerics and speculative work.** Gemini flagged possible divergence between batch and serial verification and repeated anchor/draft work. Prior NodeLift experiments already found selected top-token differences, but did not identify a specific kernel as the cause. The deferred-draft optimization remains disabled by default; no new speed claim is made here.
7. **Model retained after certain load failures.** Static inspection indicates that a model loaded before a later architecture or context error can remain owned by the engine until a subsequent load or handle destruction. This is retained allocation, not an established permanent leak. Fault-path measurement remains open.
8. **Other Gemini suggestions need qualification.** The two sampled chat prompts did not exhibit a duplicated initial BOS. `vocab_hash` is described as a token-ID semantics check, with the host performing tokenization, so missing BPE merges alone do not prove a mismatch in that narrower contract. The UTF-8 replacement concern does not apply to the separately returned raw `bytes_hex`; downstream handling still needs review.

The default branch is newer than the binary prerelease tag. The original binary and tag remain unchanged. Release notes now link the corrections and explicitly warn that the chat input limitation remains in the binary.
