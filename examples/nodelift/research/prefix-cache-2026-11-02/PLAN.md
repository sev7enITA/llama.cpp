# Prefix cache microbenchmark plan

Frozen before measurement on 2 November 2026. Evaluate the already existing native longest-common-prefix KV reuse mechanism directly, not a controller change. On the same loaded Llama 3.1 8B model, compare cold reset/prefill with a retained prefill in which a previously computed prefix has a stale tail. The test request shares 256 or 1024 exact token IDs with the priming request and appends a distinct suffix. Each arm is primed outside the timing window identically; the cold arm additionally resets before timing. Randomize arm order within each paired observation using a fixed seed. Six pairs per prefix size. Measure synchronous prefill wall time and prefill plus a 16-token greedy draft call, then compare output tokens and EOS. First-token latency is not measured separately. Retain all observations and mismatches. Reusing the exact token sequence is a synthetic repeated-context case, not a measurement of a real multi-turn controller or phone. No model-load time, live HTTP, privacy isolation, cancellation, eviction or thermal/energy measurements are included. One session on one Mac cannot establish general speedup or statistical confidence. Requested GPU offload is not independently attested. No runtime default is changed.

Pre-measurement correction: the first generated synthetic text exceeded the 2048-token context and failed during tokenization before any timed observation. The repeated text was shortened; the frozen sizes, number of pairs and analysis remain unchanged.

Post-measurement clarification: 256 and 1024 identify the synthetic base lengths. In the recorded Llama run, each separately tokenized suffix also began with the same BOS token, so the exact common prefixes were 257 and 1025 tokens. Results are retained unchanged; see the README.
